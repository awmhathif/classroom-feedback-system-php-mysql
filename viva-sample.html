Questions and answers

About the project

Tell me about your project.

It's a web based classroom feedback system. A teacher creates a class with a join code, prepares a feedback round from ready questions and opens it for a set time. Students answer once, and nobody can tell who said what. When the round closes with enough answers, the teacher sees averages, the spread of scores and comments, hides abusive comments, replies to the class and compares rounds. It's built with PHP, MySQL, HTML, CSS and a little JavaScript on XAMPP.

What problem does it solve?

Students don't criticise a teacher honestly if they think they can be identified. Paper forms can be recognised by handwriting and are slow to count; open online forms let one student answer many times; forms that stop that usually record who answered. Students also rarely hear what was done with their feedback. This system gives one answer per student without linking answers to students, hides results with too few answers, and has a reply.

Technology and architecture

Why PHP and MySQL, and why no framework?

They run on almost every web host and come together in XAMPP. I used plain PHP so I could understand and explain every line. A framework like Laravel would do sessions, CSRF and queries for me, but then I couldn't show how they work.

Explain the architecture.

Three tiers: the browser (HTML, CSS, a little JavaScript), the web server (Apache running PHP), and the database (MySQL). The browser requests a page, PHP runs, asks MySQL for data with prepared queries, builds the HTML and sends it back. The browser never talks to the database directly, so every rule is checked on the server.

Database

Explain your tables and relationships.

Seven tables. users holds students and teachers. classes belong to a teacher. enrolments links students and classes (many to many). rounds belong to a class, and questions to a round. participations records which student answered which round. answers holds what was answered, linked to the round and the question but not to any student.

How does the database keep answers anonymous?

Who answered and what was answered are in two tables with nothing joining them. participations has only round and student: no time, no running number, nothing about the answers. answers has no student id and no time, and its id is a random number, so the order of rows says nothing about who answered first or which answers go together. Both are written in one transaction, so the counts always match.

Rounds and results

Explain the round statuses.

A round starts as draft: the teacher edits its questions and can delete it. Opening makes it open: the questions are locked, students can answer, and the teacher can extend it or close it early. It becomes closed when the closing time passes or the teacher closes it, and it never opens again. Show: the state diagram in the report.

What must be true before a round can open?

The class has at least 4 students, the round has at least one rating question and 1 to 12 questions of 5 to 200 letters, and the closing time is in the future and within 60 days. Each failure gives its own reason. A class of 3 can never show results, so opening is refused rather than wasting students' time.

Security

How do you prevent SQL injection?

Every query with user input is a prepared statement: $conn->execute_query($sql, [values]) with ? placeholders. The SQL and the values reach MySQL separately, so input can never change the query. Show: any query, for example login.php.

How do you prevent XSS?

Every value from users or the database is printed through my e() function, which uses htmlspecialchars. Typed HTML or script shows as text instead of running. Show: includes/functions.php, then any page.
